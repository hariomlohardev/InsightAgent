# Level 4 — Universal Connectors: Live Data & Multi-File Intelligence (OSS)

> **From "upload a CSV" to "connect anything, join everything."**

---

## Goal

Connect **live data** (Postgres, MySQL, SQLite, BigQuery, Google Sheets) and **multi-file** (CSV+CSV, CSV+Excel) with **DuckDB federation** and **SQL-in-English**. After Level 4, you can say *"Join sales.csv with targets.xlsx on Date, show budget vs actual by Region"* and get a chart — or write `SELECT * FROM sales WHERE region='West'` and see results.

## Success Criteria

- [ ] **Connectors:** UI + API to add `Postgres`, `MySQL`, `SQLite`, `BigQuery` (via service JSON), `Google Sheets` (via API key) — all tested via `tests/test_connectors.py` with mocked drivers; `SQLite` + `sample_data/*.csv` work fully in CI without external DB
- [ ] **Live query:** `POST /api/connectors/{id}/query {"sql": "SELECT ..."}` returns `result`+`chart` (reuses L1 chat pipeline) with 5s timeout, read-only (blocks `INSERT/UPDATE/DELETE/DROP` via AST + DuckDB `access_mode='read_only'`)
- [ ] **Natural-language to SQL:** `POST /api/chat` with `dataset_id` that is a connector (or `query` contains `SELECT`) → `planner` routes to `sql` intent → `coder` generates `duckdb.query` code, not pandas groupby
- [ ] **Multi-file JOIN:** In `Datasets` list, select 2-3 files → `POST /api/datasets/join {ids: [id1,id2], on: "Date", how: "left"}` → new dataset `joined_{ids}` with `lineage` in `meta.json`; chart from join works
- [ ] **Google Sheets:** Paste share link → backend fetches via `gspread` or `requests` + `pandas.read_csv` (export link), caches 60s
- [ ] `pytest` 60+ tests (add 10), `py_compile` clean, no regression on L1-L3; `README` adds Connectors section + SQL examples
- [ ] `STORAGE_PATH` now also holds `storage/connectors/{id}.json` (encrypted DSN in L7, plain in L4 OSS with warning)

## Context & Current Facts

**L3 delivered:**
- Datasets are single-file `data.csv` + `versions/`, dashboards are file-based snapshots, chat handles 15 patterns, cleaning versioning works.

**Pain:** Users have data in Notion, Sheets, Postgres. They export CSV manually, upload, repeat daily. Want live: "My Postgres sales table updated, dashboard should reflect". Want join: "CSV + targets Excel".

**Tech already in repo:**
- `duckdb` is installed (`1.5.5`) and in `safe_globals` (`executor.py`), but not yet used for connectors — only in fallback comments.
- `pandas` reads CSV/Excel, `plotly` charts, `openpyxl` present.

## Constraints & Non-Goals

**Constraints:**
- Keep MIT, keep filesystem + `dataset` abstraction (connector is a virtual dataset, still `dataset_id`)
- No new frontend framework — Streamlit, add `🔌 Connect` tab
- No write to external DB — **read-only** all queries (security)

**Non-Goals (for L4):**
- No Mongo/Redis/Elastic connectors (defer to post-L8 marketplace)
- No cron sync (L6 scheduling will add `sync every hour` on top of L4's live query)
- No cross-dataset dashboard join UI builder (API join is enough; visual builder in L5)

## Key Decisions

| Decision | Recommended | Why |
|----------|-------------|-----|
| **Connector abstraction** | `Dataset` is either `file` (L1) or `connector` (L4). Both have `dataset_id`, `meta.json` (`type: "file"|"connector"`, `connector: {kind, dsn, table, sql}`), and `profile` generated by live `SELECT * LIMIT 5` + `DESCRIBE`. `storage.load_dataset_df` checks `type`: if `connector`, call `connector_service.fetch_df` (runs `SELECT * LIMIT 500` via driver) | Alt: separate `connectors` table adds complexity; unifying as dataset lets chat/dashboard reuse same `dataset_id` without UI changes |
| **SQL engine** | `DuckDB` for federation (`ATTACH 'postgres://...' AS pg (READ_ONLY); SELECT ... FROM pg.table JOIN df1 JOIN df2`) + direct driver for Postgres/MySQL/SQLite | Alt: `SQLAlchemy` alone is driver-specific, no cross-source join; DuckDB does `postgres + csv + sheets` in one query, already installed |
| **Google Sheets** | MVP: `requests.get(f"https://docs.google.com/spreadsheets/d/{id}/export?format=csv")` → `pandas.read_csv(StringIO(text))` (no OAuth for public sheets); for private, prompt for `SHEETS_API_KEY` and use `gspread` | Alt: full OAuth is L7 enterprise; public export covers 80% of Sheets users |
| **Join** | Explicit `POST /api/datasets/join` with `on`, `how` (inner/left/right), creates new `dataset_id` with `lineage: [id1,id2]` and `join_on`; UI shows lineage badges | Alt: auto-join detection (LLM infers keys) is flaky; explicit is reliable for L4 |
| **Security** | Block `INSERT/UPDATE/DELETE/DROP/CREATE/ALTER` via `sqlglot` parse or simple keyword blocklist in `planner` + `security.validate_sql(sql)`; run queries with `read_only` user / DuckDB `read_only` | Alt: no block is dangerous; allowlist `SELECT`+`WITH` only is safest for OSS |
| **NL to SQL** | Extend `coder.generate_code` with `sql` branch: `code = f"import duckdb\\nresult = duckdb.query(\"\"\"{sql}\"\"\").to_df()\\nfig = px.bar(...)"` where `sql` is either user's raw SQL or LLM's English→SQL translation (when `OPENAI_API_KEY` set) | Alt: pure LLM English→SQL is needed but fallback is raw SQL passthrough so OSS works without key |

## Recommended Approach

Add **three surfaces**:

1. **Connector service** `app/services/connector_service.py` + `core/connectors.py` (driver helpers) + `storage` connectors.
2. **API** `api/connectors.py` + `api/datasets.py` extension for `join`.
3. **Frontend** `🔌 Connect` tab in Streamlit.

Keep `executor` unchanged — it already has `duckdb` in `safe_globals`.

### Data Flow

```
Connect → POST /api/connectors {kind: "postgres", dsn: "...", table: "sales"} → connector_id (which is also dataset_id)
        → profile = fetch sample rows + describe → meta.json (type=connector)
Chat (NL) → planner sql → coder duckdb.query → executor (same sandbox) → result+chart
Chat (SQL) → user types "SELECT ..." → same path, sql is passthrough
Join → POST /api/datasets/join {ids: [csv_id, sheet_id], on: "Date"} → new dataset_id (type=file, lineage)
Dashboard → can use connector dataset_id like any other (snapshot)
```

## Risks / Rollback

| Risk | Mitigation | Rollback |
|------|------------|----------|
| `DSN` contains password in plain JSON (L4 OSS) | Add `⚠️ OSS stores DSN plain; use env var for prod` warning; L7 encrypts | Revert to prompt "Use env var, not UI" |
| `Google Sheets` export fails for private sheets | Show error "Make sheet public or add SHEETS_API_KEY" | Keep as known limitation |
| `validate_sql` blocks legitimate `WITH` queries | Allow `WITH` + `SELECT` + `UNION`; block only DML/DDL | Relax blocklist |
| Join on wrong key creates Cartesian blowup | Show `profile` common columns, warn if `on` not in both | Require explicit `on` |
